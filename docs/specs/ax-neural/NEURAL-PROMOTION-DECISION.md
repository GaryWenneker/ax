# Neural promotion decision — recovery candidate

**Absolute path:** `/Users/gary/io/ax/docs/specs/ax-neural/NEURAL-PROMOTION-DECISION.md`  
**Date:** 2026-11-16

## Decision

Do not promote the recovery selector, prediction gate, learning prior, or ONNX fusion. Production defaults stay unchanged: `SEMANTIC_WEIGHT` is 0, hash-v1 remains the memory embedder, and the default binary does not link ONNX.

## Why

| Gate | Evidence |
|---|---|
| Meaningful improvement on independent tasks | Not shown. Live `score_coding` recall on 12 non-locked questions has MRR 0.667 and Recall@3 0.667. BM25 on the same lists has MRR 0.625 and the same recall. Hash cosine on those questions is MRR 0.710 because it does not run the live filters: reciprocal-rank fusion at vector weight 0.5 and full-text weight 0.3, then a drop of any hit below 85% of the best term coverage, and an abstention when the best coverage is below 25%. Skipping that drop with the existing bench flag `AX_MEMORY_BENCH_RAW` raises the same 12 questions from MRR 0.667 to 0.750, Recall@3 from 0.667 to 0.750, and Precision@3 from 0.222 to 0.250. The same flag fails `preflight_abstains_when_only_a_single_query_term_overlaps`: a lute query returns the Spotify callback memory because both texts contain `404`. With the floor left on, that test passes and the other 42 brain tests passed under the flag. Skipping only the 85% relative cutoff, and keeping the absolute abstention, leaves the 12-question scores at MRR 0.667, Recall@3 0.667, and Precision@3 0.222. The lute query still abstains. Classifying every relevant memory on that slice, the only one that enters the raw top-3 and is absent from the production top-3 is `rename:renamed-symbol`: the prompt is `loadturn` and the memory says `save_turn`, so the content-token overlap is zero. Seven relevant memories are already in both top-3 lists with enough overlap to pass the ratio floor. None of the raw-only gains are a one-token overlap or a two-token overlap below 25%. The coding-slice gain and the lute/404 false injection are the same zero-coverage abstention, so the floor stays. An experimental identifier-stem match, used only when `AX_MEMORY_BENCH_IDENTIFIER_STEM` is set, counts a query token as a hit when the shared piece is at least 4 characters and at least half the shorter identifier. On these 12 questions it raises MRR from 0.667 to 0.750, Recall@3 from 0.667 to 0.750, and Precision@3 from 0.222 to 0.250. `loadturn` then returns `renamed-symbol` first and the sibling `hop-writer` second. The coding abstention question stays empty, and the four locked-family result counts stay the same. The brain suite passes 43/43 with the flag off and 43/43 with the flag on, including the lute query. The shared piece in this pair is 4 characters, the rule's minimum, so the slice does not independently confirm the threshold. On the labeled live-probe titles, which were not used to choose the rule, the same match adds 4 hits from abstention queries onto delivery titles and 12 hits between delivery titles. `pudding` matches the title that contains `including`. The flag stays off. A separate boundary rule stem-matches only when a token contains `_`, `-`, or an internal capital. It keeps the same coding-slice scores and still abstains on the lute query. Abstention probe queries add no extra hits. One delivery title still matches another: the prompt about compact memory content matches the title that contains `ax-context`. `AX_MEMORY_BENCH_IDENTIFIER_BOUNDARY` stays unset. The free stem rule was not edited. A third rule counts only a shared prefix or suffix on an identifier-shaped token. It keeps the coding-slice scores, changes only the `rename` list, leaves the locked lists unchanged, and adds no probe-title crosses. `content` does not match `ax-context`. The lute query still abstains, and the brain suite passes 43/43 with `AX_MEMORY_BENCH_IDENTIFIER_AFFIX` set. That flag stays unset because the affix limit was chosen from these same pairs. On the unused LoCoMo file, production `recall_for_prompt` and the affix flag score the same 1,982 questions: MRR 0.28768439767430687, Recall@3 0.3118159030116649, Precision@3 0.1177262024890693, NDCG@10 0.3125073748573058. Zero lists change. That run does not use `ax_text_rank`. On 617 documented public functions outside `ax-memory` and `ax-neural`, the query is the existing doc comment and the document is the signature line. Three runs with random memory ids kept 55 list changes, 12 MRR gains, and 3 MRR losses, while the MRR delta moved between 0.00515036916981812 and 0.0052854312983972584. One run with stable memory ids scores production MRR 0.17747420956497137 and affix MRR 0.182903707133853, a delta of 0.005429497568881642, with the same 12 gains and 3 losses. A second run with the same stable ids matched those scores. The flag stays off. The rule was not edited. This set was extracted for the measurement and is not a pre-existing benchmark. The neural fills did not beat the hash list either. The 0.626 to 0.640 MRR change is leave-one-out inside the same families and skips the evidence floor. |
| Mandatory context and project isolation | Unit-tested in `recovery.rs` only. Not observed in a live agent turn. |
| No unacceptable ranking regression | Replacing hash with ONNX on 15 non-locked questions lowers MRR from 0.710 to 0.691. Filling only the zero-score tail from ONNX lowers MRR from 0.7098214285714285 to 0.7083333333333334 on 12 questions. The synonym-tail fill ties 0.710. The ranking-prior still drops MRR by 0.214 on its fixture eval. |
| Latency and memory budget | Not measured for this candidate. |
| Rollback | The flag defaults to off and production `rank::plan` does not call `select_context`, so leaving it unused is the rollback. |
| Reproducible agent evidence | Absent. The isolated recovery command is 10 passed, 0 failed. The one-thread library suite is 160 passed, 0 failed. That does not show better coding outcomes. |

The preliminary live-benchmark gaps remain execution variance and a 420-second timeout, not a measured retrieval win. See `NEURAL-FAILURE-ANALYSIS.md`.

## Classification

| Component | Class |
|---|---|
| Production retrieval | `production_validated` as the baseline |
| `select_context` recovery selector | `not_sufficiently_evaluated` |
| Confidence-gated prediction | `implemented_not_beneficial` until an independent calibration set exists |
| Ranking-prior learning | `implemented_not_beneficial`. The broad pairwise hinge lowers locked MRR from 0.714 to 0.692. The top-miss hinge ties 0.714 and does not raise it. |
| ONNX fusion | `rejected_for_production`. Full replacement raises recall and lowers MRR. Zero-score ONNX fill also lowers MRR, from 0.710 to 0.708. |
