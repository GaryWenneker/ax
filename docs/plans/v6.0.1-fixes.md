# SPEC: v6.0.1 — green CI and a correct version pointer

Tier 2 (bug fixes). Each fix starts with a test that fails on the current code.

## Fix 1 — `escape_regexp` panics (clippy `invalid_regex`)

`crates/ax-context/src/directory.rs` builds `[.*+?^${}()|[\]\\]`. In Rust's regex
syntax the inner `[` opens a nested class, so the pattern never compiles and every
call panics on `unwrap()`.

- `escape_regexp("a.b*c")` returns a pattern that matches the text `a.b*c` and not `axbbc`.
- `escape_regexp("x[1](y)")` returns a pattern that matches `x[1](y)` literally.
- Fix: use `regex::escape`. `cargo clippy -p ax-context -- -D clippy::correctness` passes.

## Fix 2 — `cycles_api_path_handlers_work` needs a local index

`crates/ax-mcp/tests/new_tools_smoke.rs` opens the repo root, which has no `.ax/`
on CI, and fails with "project not initialized".

- The test builds its own project in a temp dir (`Ax::init` + `index_all` on two
  small Rust files that call each other) and runs `ax_cycles`, `ax_api` and `ax_path`
  against it, with the same assertions as today.
- Passes with no `.ax/` in the repo root. No assertion gets weaker.

## Fix 3 — Windows test build fails on `std::os::unix`

`crates/ax-web/src/project_purge.rs` test `symlink_is_refused` calls
`std::os::unix::fs::symlink`.

- The test is marked `#[cfg(unix)]`. Creating symlinks on Windows needs admin rights
  or developer mode, so it cannot run reliably on CI there.
- `cargo test -p ax-web --lib --no-run --target x86_64-pc-windows-gnu` is not available
  locally; the Windows CI job is the check.

## Fix 4 — `/releases/latest.txt` returns `v3.0.0`

`site/netlify/functions/latest-release.ts` does not find the bundled `latest.txt`
at runtime and falls back to a hardcoded `v3.0.0`.

- The function also looks in the paths Netlify uses for `included_files`
  (`<cwd>/site/public/releases/latest.txt` and relative to the bundle).
- When no file is found it answers **503** with `latest release unknown`, never a
  made-up version (fails closed; installers use the GitHub API first).
- Real check after deploy: `curl https://getax.wenneker.io/releases/latest.txt`
  returns `v6.0.1`, and with `Accept: text/html` the HTML page shows the same version.

### Revision (during implementation)

A preview deploy with the extra lookup paths answered 503: the bundled file is not at
any of those paths on Netlify. New approach:

- `npm run build` first runs `scripts/write-latest-version.mjs`, which writes
  `netlify/latest-version.json` (`{"version":"v6.0.1"}`) from `public/releases/latest.txt`.
  An empty or missing `latest.txt` makes the build fail.
- The function imports that JSON, so the version is part of the bundle.
- `createHandler(version)` is tested for plain text, HTML and 503 (empty version).
- Real check on a preview deploy before the release.

### Fix 5 — Windows-path tests on Unix

`ax-quality` `bootstrap::tests::{legacy_prefix_from_workspace_folder,
resolves_placeholder_to_folder_name}` and `ax-usage`
`savings::tests::cursor_transcript_path_filter` use `C:\...` paths. On Unix a
backslash is not a separator, so the folder name comes out as `C:-gary-Contoso`.

- The existing tests get `#[cfg(windows)]`; their assertions stay unchanged.
- Each gets a Unix twin (`#[cfg(unix)]`) with the same assertions on a `/` path
  (`/home/gary/Contoso` → `Contoso`; `/home/me/.cursor/projects/p/agent-transcripts/uuid/uuid.jsonl`
  matches, `.txt` and `other.jsonl` do not).
- A throwaway mutant in each function under test must turn its Unix twin red.

### Fix 6 — flaky `resolve_sonar_repo_names_skips_missing_git_roots`

`temp_workspace()` names the dir after the clock. On macOS two parallel tests get the
same microsecond, so the neighbour test's `beta` lands in this test's workspace
(alone: pass; together: 2 of 5 runs failed).

- `temp_workspace()` uses `tempfile::tempdir()` (already a dev-dependency).
- `cargo test -p ax-ship --lib git_root` passes 20 runs in a row.
